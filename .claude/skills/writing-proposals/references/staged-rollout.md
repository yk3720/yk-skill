# 段階的提案（試用 → 本格化）

試用・PoC・パイロットを含む提案で、対話で足りない材料を埋める。詳細手順は本ファイル、チェックは [output-quality.md](output-quality.md) の「段階的提案」。

## 聞く材料（⑥ · 段階的提案があるとき）

| # | 聞くこと | 例 |
|---|----------|-----|
| 1 | 試用期間 | 2週間 / 1か月 |
| 2 | 成功条件（Go） | 2〜3指標。数字がなければ定性＋「試用中に計測」 |
| 3 | 誰が判断するか | 読者＝判断者の肩書で書く（「上長」で曖昧にしない） |
| 4 | 報告形式 | 何を・いつ・誰に報告するか |
| 5 | フォールバック | 本格化不可時の代替（構成変更・見送り等） |

## 出力に必ず分ける2層

```
本日のお願い  … 方向性・試用開始など、今日 Yes/No したいこと
後日の判断    … 試用後の Go/No-Go・予算・本番化（今日の Yes/No に含めない）
```

## 成功条件の書き方

- 「効果が見えたら」だけで終わらせない
- 定性のみでも可：`明らかに楽になった` + `改善幅は試用中に計測`
- 数字はユーザー確認後のみ（創作禁止）

## ランニングコスト（SaaS・外部クラウド）

- 月額は **目安・変動あり**（従量・為替）
- **本番構成と金額を対応させる**（ユーザー確認後。試算表があればそれを正とする）
- 今日の判断依頼にしない → `試用後に判断者と改めて相談` と明記
