# 洗練の定義

## ユーザー基準（SSOT）

**洗練された文章**とは、多すぎても少なすぎても伝わらない状態を避け、**これ以上削っても、足してもわかりにくくなる**文章のこと。

| 状態 | 問題 |
|------|------|
| 多すぎる | 読む負荷が上がり、要点が埋もれる |
| 少なすぎる | 判断材料が欠け、誤解や追問が増える |

## 作業の原則

1. **正本・方針 SSOT の事実は欠落させない**（短くしても意味を落とさない）
2. **同じことを言う段落の重複を削る**（スキマ読み用の意図的重複は残す場合、理由を設計メモに書く）
3. **用語・語尾・番号表記を揃える**（例: 1.2.3. / 「伺いたい」で統一）
4. **読者が次に何をすればよいか**が 1 通りに読める

## 終了条件（ループ）

| 重大度 | 扱い |
|--------|------|
| **ブロッカー** | 必ず修正し、再チェック |
| **中** | 必ず修正し、再チェック |
| **低** | 1 回まとめて直す → 再チェック。残ればユーザーに提示して終了可 |

**ラウンド上限:** 原則 3。上限に達してもブロッカー・中が残る場合はユーザーに報告し、続行するか確認する。

## サブエージェントの判定語

各ラウンドの統合判定は次のいずれか 1 つ:

- **GO** — ブロッカー 0 · 中 0（低は許容）
- **GO with notes** — 送信・採用可だが低が残る（1 回修正後のみ）
- **要修正** — ブロッカーまたは中が 1 件以上

ループ継続: **要修正** のときのみ（低だけのときは上記に従い終了可）。
