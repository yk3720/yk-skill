# 文体の確認とルーティング

**毎回必須:** 洗練を始める前に、ユーザーへ文体・読者を確認する。推測で文体を決めない。

## 確認する項目

| 項目 | 例 |
|------|-----|
| **読者** | 係長 · 上司 · 社内一般 · 技術者 |
| **媒体** | メール · 報告書 TXT · 図解 HTML ブロック · 提案書 |
| **トーン** | 実務敬体 · 提案 · 説明 · 自分の文体（YK） |

未指定のときは **2〜4 候補を提示**し、推奨を 1 つ示して理由を添える（`AskQuestion` または箇条書きで可）。

## 文体別 SSOT（選んだら Read）

| 文体・媒体 | 参照 |
|------------|------|
| 社内メール（YK 文体） | `writing-in-my-voice-yk` → `c:/yk-memo/04.文章/特徴.md`。社内新規の型だけ `writing-internal-mail-yk` exemplars |
| 上司向け briefmap / 図解 HTML | `creating-briefmap-yk` → copy-refinement · tone-checklist |
| 長い提案文書 | `writing-proposals` |
| 体裁共通 | `c:/yk-skill/rule/5_writing/WRITING_RULES.md` §1 |

## 案件固有

同フォルダに `資料作成方針*.md` · 設計メモ · 正本（01 等）があれば **必ず Read**。洗練で方針（何を聞く/聞かない · 用語）を変えない。

## ユーザー指定の上書き

「句点で改行」「1.2.3. にする」等、**当ターンの明示指示**は SSOT より優先する。
