# レビュー → 修正ループ

`reviewing-with-subagents` の Step 2〜4 に準拠。本スキルは **親が修正まで行う** 点が異なる。

## ラウンド開始前（親）

1. 対象 **全文** と方針 SSOT · 文体参照を Read 済みであること
2. 機械的に直せる体裁（明らかな typo · ユーザー指定の改行規則）は **先に直し**、サブには判断・文脈に集中させる

## レンズ選定（3 体以上）

`reviewing-with-subagents/references/perspectives.md` から **重複しない 3 つ以上**を選ぶ。

### 文章洗練のデフォルト・トリオ

| レンズ | 見ること |
|--------|----------|
| **報告先（受け手）** | 読者が誤解しないか · 負荷（長さ・専門語）· 次の行動が明確か |
| **編集・様式** | 冗長 · 語尾ゆれ · 見出し・番号 · 同じ説明の三重化 |
| **方針整合（案件）** | 正本・`資料作成方針` と矛盾しないか · 聞く/聞かない論調 |

対象に応じて差し替え:

- 外向き・規程: **コンプライアンス** を追加または第三者と入替
- 技術手順: **技術的正確性（SME）** を追加
- 提案・説得: **報告者** + **レッドチーム**

## 並列起動（1 ターン）

`Task` を **複数回並列**。各 `prompt` に含めるもの:

- 採用レンズ名 + その視点の定義（何を見る/見ない）
- **対象全文**（パスだけにしない）
- 方針 SSOT の要約（あれば）
- 文体（Step 0 で合意したもの）
- 出力形式（下記）
- **修正はしない**（readonly 推奨）

```markdown
## 採用レンズ
（レンズ名）

## この視点の内容
（1〜3 文）

## 判定
GO / GO with notes / 要修正 のいずれか 1 つ

## 所見
（重大度: ブロッカー / 中 / 低 · 根拠 · 具体的な修正案）
```

## 親の統合と修正

1. 全サブの所見を **重大度でマージ**（同趣旨は 1 件に）
2. **ブロッカー → 中 → 低** の順で修正を適用
3. 対立する指摘は **方針 SSOT · 読者利益** で決める（単純多数決しない）
4. 修正後、ファイルまたはチャットに **全文** を出す

## 再チェック

- 統合判定が **要修正** → 次ラウンド（更新全文を渡す）
- **GO** → 完了
- **GO with notes**（低のみ）→ 低を 1 回直してから **1 体**の総合レビューで GO 確認。残ればユーザーへ報告

総合レビュー用プロンプト例: 「3 視点（受け手・編集・方針）で改訂全文を再判定。ブロッカー・中があれば列挙、なければ GO。」

## アンチパターン

- サブに修正まで任せて親が統合しない
- 1 体だけで「多角的」と称する
- 正本を Read せずに短くする
- 低指摘を無限ループ（3 ラウンド上限）

## 実績からの体裁メモ（任意）

社内メール等で効いた整形（ユーザー明示時）:

- 句点（。）のあとで改行
- 手順は `1.` `2.` `3.` で統一

案件の `writing-internal-mail-yk` exemplars に追記するかはユーザー判断。
