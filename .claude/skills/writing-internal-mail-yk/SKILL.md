# Writing Internal Mail（YK）

**発火条件:** ユーザーが **「私の文体で」** と明示したとき**のみ**。メール・送付・係長などの単語だけでは起動しない。

**用途:** 依頼された文（主に社内メール1通）を、貼り付け可能なテキストで出す。

## 参照（着手時に Read）

| 順 | ファイル | 役割 |
|----|----------|------|
| 1 | [references/patterns.md](references/patterns.md) | 口調 · ■構成 · 判断の載せ方 |
| 2 | [references/exemplars.md](references/exemplars.md) | 実例（最優先で寄せる） |
| 3 | 案件の `資料作成方針*.md`（あれば） | 送付論調 · 何を聞く/聞かない |

体裁の共通規則: `c:/yk-skill/rule/5_writing/WRITING_RULES.md` §1

## ワークフロー

### 1. 材料を揃える

コードベース・同フォルダ資料から Read できることは自分で調べる。ユーザーに聞くのは不足分だけ。

- 宛先（例: `XXXX係長`）
- 件名の核 · 何を送るか（図解 · URL · 添付名）
- ログイン情報 — **プレースホルダのまま**（`アドレス：XXXX@gmail.com` / `パスワード：XXXXXX`）
- 面談前に伝える判断事項（金額承認は求めない）
- 保存先パス（指定があれば `.txt` で出力）

### 2. 起草

- [patterns.md](references/patterns.md) と [exemplars.md](references/exemplars.md) に寄せる
- `■` でブロック分け · 結論・お願いを先に
- 押し付けを避け「〜と考えています」「〜つもりです」を適宜使う
- 任意資料は「面談前の必読ではない」「お時間のあるとき」と明記

### 3. 出力

- **そのまま貼れるプレーンテキスト**（件名行から署名まで）
- ユーザー指定時はプロジェクト内に `*_送付メール_*.txt` 等で保存
- 署名・宛名の `〇〇` / `XXXX` はユーザー差し替え用として残す

## 境界

| 使う | 使わない |
|------|----------|
| 係長・上司への送付/事前連絡メール | 図解 HTML · 01/03 調査報告の本文 |
| 短い「ご判断お願い」2〜3点の事前告知 | `writing-proposals` 向けの長い提案書 |
| 送付メール + 読み方の口頭案内の文面化 | チャットでの技術説明 · 既存文の洗練（`refining-copy-yk`） |

## 実例の更新

送信してよかったメールができたら、[exemplars.md](references/exemplars.md) に日付付きで追記する（`creating-skills` 完了時またはユーザー依頼時）。
