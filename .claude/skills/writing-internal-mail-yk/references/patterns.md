本人の口調の正本は `c:/yk-memo/04.文章/特徴.md` と直近の確定稿。本ファイルは補助。体裁の共通規則は `c:/yk-skill/rule/5_writing/WRITING_RULES.md` §1（■階層 · 結論先出し）。

## 口調

| 使う | 避ける |
|------|--------|
| です・ます（係長・上司向けの実務トーン） | 過剰な敬語の連打 · 論文調 |
| 「〜と考えています」「〜つもりです」 | 「〜すべきです」の押し付け |
| 「お時間のあるときにご覧いただければ」「面談前の必読ではありません」 | 「興味がなければ」（関心の決めつけになりやすい） |
| 「面談でご相談できればと思います」「方針を伺いたいと考えています」 | 「この段階では決めなくてよいと思っています」（部下が決めている印象） |
| 所要時間の目安（例: 5〜10 分） | 同じ「触ってほしい」の繰り返し |
| 「課内本番に使ってよいか」（図解と用語統一） | 「業務で使ってよいか」（範囲が広く読める） |
| Copilot 等は別件と1行で切り分け | 生成 AI 規程と混同させる |

## 構成（送付・提案メール）

1. 件名 — 何の話か一行で
2. 宛名 — `XXXX係長`（ユーザーが差し替え）
3. 挨拶 · 自己名 — `お疲れ様です。〇〇です。`
4. **冒頭1〜2文で用件**（試作完了 · 資料送付 · 面談前に触ってほしい）
5. `■` 見出しでブロック分け（お願い · 任意資料 · 面談で相談すること）
6. URL · ログイン — プレースホルダをそのまま残す（ユーザー追記）
7. 締め · 署名 `〇〇`

## 判断依頼の載せ方（社内合意系）

- **今聞くこと** と **後で面談** を分けて書く
- 金額は「判断依頼」にしない。「参考は資料にあり」「有償 OK 後に具体的な話」と書く
- 図解/HTML がメイン · テキスト資料は任意、とメールで案内する（資料本文には書かない方針と整合）
