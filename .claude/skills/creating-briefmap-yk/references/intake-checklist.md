# BriefMap — Phase 0 必須確認（ゲート）

**未充足の項目がある間は HTML 生成・デプロイに進まない。**  
**一般論・業界標準・「たぶん」で穴埋めしない。** 推測が必要なら AskQuestion でユーザーに確認する。

## 必須項目一覧

| # | 項目 | 取得元 | 未指定時 |
|---|------|--------|----------|
| 1 | **正本**（txt/md/パス） | ユーザー指定 | 停止 · 正本を求める |
| 2 | **preset** | supervisor / hybrid / report-only | 上司向けは **supervisor 推奨** → 確認 |
| 3 | **WRITING タグ** | 【共有】【提案】【相談】【依頼】等 | preset から提案 → **確認** |
| 4 | **読者**（誰に出すか） | 正本・ユーザー | **1問で確認**（既定: 同部署エンジニア上司） |
| 5 | **お願い・判断項目** | 正本の箇条書き | hybrid/proposal で **必須**。無ければ停止 |
| 6 | **調査結果（事実）** | 正本 | report/hybrid で **必須**。無ければ停止 |
| 7 | **選択肢と月額等の数値** | 正本 | 表に載せる数字は **正本のみ**。不足なら確認または該当行を省略 |
| 8 | **推奨案と理由** | 正本 | 正本に無ければ「推奨なし」またはユーザー確認 |
| 9 | **リスクと対策** | 正本 | 正本に無ければセクション省略。**捏造しない** |
| 10 | **slug** | ユーザーまたはテーマから提案 | **確認** |
| 11 | **納品** | 既定 **ローカル**（ユーザー指定パス） | surge は**当ターン明示時のみ** |

## AskQuestion の優先順（1問ずつ）

1. 正本が複数ある → どれが **正** か
2. preset が曖昧 → hybrid / report-only / proposal-only
3. お願い項目が正本に無い（proposal/hybrid）→ 判断してほしい N 点
4. 数値・構成表が部分的 → 載せる行をユーザーと確定
5. 推奨が複数記載で矛盾 → どれを図解正本にするか
6. 納品先（ローカルパス · surge も必要か）

## WebSearch を許可するケース

- 正本に「要調査」と明記された料金・規約
- 正本の URL が古い可能性があり、ユーザーが最新確認を依頼

**禁止:** 正本に無い推奨構成を Web 調査だけで組み立てること。

## writing-proposals へ委譲

次のときは briefmap より先に `writing-proposals` を実行:

- 正本が無く、思いつきレベルの依頼のみ
- お願い・根拠・選択肢が Phase 0 で確定できない

テキストが固まってから briefmap Phase 0 に戻る。
