図解依頼の流れ（代表例）

「図解して」とだけ言ったときは、まず形式を選び、あとから専用の手順書に渡す。

「図解して」 形式の受付 文系 / 理系 / 社内周知 / 上司向け / 汎用

その他: E2E は「設計 → spec 実行」、Git は「コミット → push」の順が基本。

明示したときだけ動く手順（3 件）

  • コミット — 「コミットして」と言ったときのみ
  • push / PR — 「push して」「PR を作って」と言ったときのみ
  • スキル台帳の再生成 — 「スキル台帳を更新」と言ったときのみ

意図しない Git 操作や台帳の上書きを防ぐための設定。

所見

  • 日常作業はカテゴリ単位で探すと早い（例: 図解 · テスト · 文書）。
  • 詳細な名前一覧はテキスト索引が正本。本資料と Mermaid 図は俯瞰用。
  • スキル追加時は索引と図をあわせて更新する運用が必要。
